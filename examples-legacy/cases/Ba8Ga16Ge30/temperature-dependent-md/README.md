# Ba8Ga16Ge30 temperature-dependent NVE data

This case reproduces the molecular-dynamics sampling protocol used by the
upstream hiPhive BaGaGe thermal-conductivity example, using its published
static Model-4 force-constant potential directly. No MLFCS fit, IFC conversion,
or atom reordering occurs in this workflow.

The input FCP includes FC2, FC3, and FC4 terms with a maximum body order of two:

| Order | Cutoff |
| --- | ---: |
| FC2 | 5.40 A |
| FC3 | 4.35 A |
| FC4 | 4.35 A |

For each of 300, 400, 500, and 600 K, `run.py` uses the 54-atom upstream
reference structure repeated as `2x2x2` (432 atoms), equilibrates for 10,000
Langevin steps at 1 fs, then runs 5,000 NVE steps at 1 fs. ASE retains the
initial NVE state and writes one additional frame every 50 steps, giving the
same 101 frames per temperature as the upstream workflow.
The initial velocities are seeded separately per temperature so reruns are
reproducible.

Run all four temperatures:

```bash
uv run python examples/cases/Ba8Ga16Ge30/temperature-dependent-md/run.py
```

Results are under `md/T{temperature}K/`:

- `nvt.traj`, `nvt.log`: equilibration, retained as provenance for the NVE start.
- `nve.traj`, `nve.log`: native ASE NVE trajectory and energy log.
- `nve.extxyz`: the 101 force-labelled NVE frames for fitting.
- `metadata.json`: temperature, sampling parameters, random seed, and FCP hash.

Once a temperature directory contains `nve.extxyz`, fit its effective IFCs with:

```bash
cd examples/cases/Ba8Ga16Ge30/temperature-dependent-md/md/T300K
uv run python fit.py
```

Every temperature directory has this local `fit.py` entry point. It matches
the upstream thermal-conductivity fit space, not the static MD potential:
FC2 and FC3 only, with `5.40/4.35 A` two-body cutoffs. Its `mlfcs/` output
contains native `mlfcs.h5`, phonopy FC2 text/HDF5, and ShengBTE/phono3py FC3.

After an effective IFC fit completes, run the temperature-specific RTA
calculation on a `3x3x3` mesh. The script reads the 54-atom
`input/reference.vasp`, expands it with `mlfcs.build_supercell(..., (2, 2, 2))`,
exports `input/mlfcs_supercell.vasp`, then lets phono3py find the primitive
cell from the resulting 432-atom VASP structure:

```bash
uv run --with phono3py python examples/cases/Ba8Ga16Ge30/temperature-dependent-md/run_rta.py \
  --temperatures 300
```

Each result is written to `md/T{temperature}K/thermal-conductivity/` as
`kappa-rta.txt`, `kappa-rta.npz`, and `metadata.json`.

## Upstream ShengBTE reference

The upstream case reports the following scalar lattice thermal conductivities
from ShengBTE, in W m^-1 K^-1.  It uses the same `2x2x2` MD cell and a `9x9x9`
ShengBTE mesh. `Regular` is its joint FC2+FC3 least-squares fit; `serial` fits
FC2 first and FC3 against the residual force. The effective IFC model remains
two-body with `5.40/4.35 A` FC2/FC3 cutoffs in both cases.

| Temperature (K) | Regular | Serial |
| ---: | ---: | ---: |
| 300 | 0.7897554104 | 0.7005384437 |
| 400 | 0.6976 | 0.6088 |
| 500 | 0.6466999525 | 0.5190360975 |
| 600 | 0.5774040711 | 0.4539887989 |

These are upstream ShengBTE reference values, extracted from
`thermal_conductivity/data/kappa_fourth_order_effective_models` at the
revision recorded in `input/source.json`. They are not a direct numerical
acceptance target for `run_rta.py`: that script uses phono3py's RTA solver,
whereas the reference calculation is ShengBTE with its own solver and isotope
settings.

Do not confuse this effective-model table with the separate PBE RTA reference
file `data.BGG.pbe.kappaRTA` in the upstream repository. Its 300 K entry is
`0.272003779 W/mK`. The three values describe different force-constant models
and/or solvers, so none is a universal material constant. The 300 K hiPhive
comparison using this case's 101-frame NVE trajectory is generated by
`md/T300K/fit_hiphive_compare.py`; it writes only ShengBTE FC3 text under
`md/T300K/hiphive/` and records the direct force comparison in `metrics.json`.
It also writes hiphive's FC2 as phonopy text and compares it directly with
`md/T300K/mlfcs/FORCE_CONSTANTS_2ND` using hiphive's phonopy reader. For the
checked 101-frame run, hiphive has force RMSE `0.0229951 eV/Angstrom` versus
MLFCS `0.0269431 eV/Angstrom`; the FC2 text difference is `0.3482%` in relative
Frobenius norm, with maximum component difference `0.0338083 eV/Angstrom^2`.

The FC3 text files are compared with `md/T300K/compare_shengbte_fc3.py`, which
canonicalizes primitive labels, periodic translation residues, and atom/tensor
permutations without dense materialization. Both files contain 3222 blocks and
the same 1110 canonical physical keys; their common-key tensor difference is
`10.6859%` relative Frobenius norm, with maximum component difference
`2.43386 eV/Angstrom^3`.

`shengbte/CONTROL` is the upstream 9x9x9 ShengBTE control input, retained with
its original 600 K setting. For an effective-FC calculation at another
temperature, change only `T` after placing the corresponding effective FC2/FC3
files in that run directory.

Input provenance is recorded in `input/source.json`. The source is the public
[hiPhive examples repository](https://gitlab.com/materials-modeling/hiphive-examples).
